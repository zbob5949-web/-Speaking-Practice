## 0. 先记住三件事

1. **单进程形态**：一个 `uvicorn` 同时提供 API 和前端页面（`app/frontend/dist` 由 `main.py` 托管）。改前端必须 `npm run build`，否则线上还是旧页面。
2. **契约在 `/openapi.json`**：前后端不靠口头约定，靠 OpenAPI。接口变了，先改后端、再看 openapi、再同步 `types.ts`。
3. **当前测试不是绿的**（见 §6），别把它当“已经完成”的依据。

## 3. 环境与启动（两人必须一致）

### 3.1 后端（不用 PyCharm）

```powershell
cd /d "D:\GIT\-Speaking-Practice\app\backend"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```
> 必须先进 `app\backend` 再启动，否则 `No module named 'app'`。
> 也可以直接跑仓库根目录的 `run_backend.py`。

### 3.2 前端两种模式

| 模式 | 命令 | 说明 |
|---|---|---|
| **生产（默认）** | `npm run build` | 产物进 `dist/`，后端 8000 直接托管。**日常验收用这个** |
| 开发（热更新） | `npm run dev` → `:5173` | 需要在 `vite.config.ts` 补 proxy，否则接口全 404 |

`vite.config.ts` 需要这一段（当前缺失）：

```ts
server: { proxy: { "/api": { target: "http://127.0.0.1:8000", changeOrigin: true } } }
```

### 3.3 环境一致性（重要）

| 项 | 约定 |
|---|---|
| Python | 3.11 ~ 3.13 均可；**两人必须同一大版本** |
| Node | 20 LTS；与 `package-lock.json` 一起提交 |
| `.env` | 放**仓库根目录**（`config.py` 按项目根定位，不看工作目录） |
| 语音模型 | `data/asr_model/`，不进 git；没有则语音降级、打字不受影响 |
| 数据库 | SQLite 单文件；测试与开发**不要同时跑**，避免锁 |
| 鉴权 | 除 `/api/auth/{login,register,guest,refresh}`、`/api/health` 外**一律要 token** |

## 4. 接口契约工作流（前后端唯一真源）

### 4.1 新增/修改接口的固定 5 步

1. **后端先定契约**：在 `models.py` / `contracts.py` 写请求体与响应体类型。
2. **实现 router + service**，确保 `/openapi.json` 里能看到。
3. **写/改 pytest**（至少覆盖 200 与 400 两条路径）。
4. **通知队友**：贴出 openapi 片段 + 变更点（字段增删、类型变化）。
5. **队友同步 `types.ts` 与 `api.ts`**，再写 UI。

> 顺序不能反。前端先写 UI 等接口，是这类项目最常见的返工来源。

### 4.2 响应约定

| 场景 | 约定 |
|---|---|
| 成功 | 直接返回对象，不包 `{code,data}` 壳 |
| 参数错误 | HTTP 400 + `{"detail": "中文原因"}` |
| 未登录 | HTTP 401 + `{"detail": "请先登录"}` |
| 资源不存在 | HTTP 404 + `{"detail": "..."}` |
| 列表 | `{"items": [...]}` 或 `{"xxx": [...]}`，字段名固定 |

### 4.3 前端同步规则

- `types.ts` 的类型名与后端类名保持一致（`SessionHistoryItem` ↔ `SessionHistoryItem`）。
- 可选字段用 `?:`，不要用 `any` 糊。
- 所有请求走 `api.ts`，禁止组件里直接 `fetch`。

## 6. 技术债清单（P0，建议第一周清掉）

| ID | 位置 | 问题 | 影响 | 方案 | 责任 | 预估 |
|---|---|---|---|---|---|---|
| **BE-1** | `routers/asr.py:23` | 每个请求 `new AsrEngine()`，重复加载模型 | 内存暴涨、首次识别极慢、1G 服务器必崩 | 改用 `asr.get_engine()` 单例（`voice.py` 已是正确写法） | 你 | 0.5h |

| **FE-1** | `src/App.test.tsx` | 37 个用例 **35 红**（落地页改主页面后失效） | 前端无回归保护 | 按新 IA 重写：先断言主页面 → 点 Chat/Profile → 再断言 | 队友 | 1~2 天 |
| **FE-2** | `styles.css` | 6751 行、16 轮补丁叠加、同名选择器多处重复 | 改一处崩三处 | 拆成 `base/tokens/layout/pages/components`，按页面收敛 | 队友 | 2~3 天 |

## 10. 常见坑（都是这轮踩过的）

| 现象 | 原因 | 解法 |
|---|---|---|
| 改了前端但页面没变 | 后端托管 `dist`，没重新 build | `npm run build` + `Ctrl+Shift+R` |
| `No module named 'app'` | 工作目录不是 `app/backend` | 先 `cd app\backend` |
| 手机长按没反应 | `http://局域网IP` 下浏览器禁用麦克风 | HTTPS 或安卓 App |
| 页面滑不动 | 嵌套 `max-height + overflow` 吃掉滚轮 | 统一 `.app-main` 为滚动容器 |
| 对话上方一大片空白 | `.chat-scroll` 被 `max-height: calc(100vh-400px)` 限高 | 去掉限高 |
| 每个请求都很慢 | `AsrEngine()` 每请求新建 | 用 `get_engine()` 单例 |
| 测试红一片但不是自己改的 | 用例与实现早已脱节 | 先对齐（BE-2） |
